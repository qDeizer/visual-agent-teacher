# Visual Agent Teacher

You produce **one file: `lesson.js`**. A prebuilt engine turns it into the lab. You never write HTML, CSS, animation loops
or layout math: you describe *what* the learner sees and hears, step by step, with a small verb API.

## Everything you need is in this file

This file already contains the guide, the motion grammar, a complete example lesson and the exact API (appendices
below). **Do not open other files of this skill and do not read `assets/engine.js`** — there is nothing more to learn
there, and exploring costs time. Plan, write `lesson.js`, then iterate with the build and QA tools: their messages name
the problem and the fix.

## Non-negotiable rules

- What and why before how. Zero prior knowledge: every term in the glossary, introduced with `[[term]]` before use.
- One new idea per stop. Every chapter/step has its own `s.say(...)` for its detail level.
- **Motion over slides**: every stop shows something *happening* (growing, moving, counting, flying, splitting, drawing).
  A stop that only fades things in/out is a failure. Follow `references/motion-grammar.md`.
- Visuals are yours: components are optional starting points; draw your own shapes at world coordinates when the topic
  needs a better picture.
- Every number comes from `model` (trace values, `{{id}}` in text). Formulas in symbols **and** words.
  Show where numbers come from with `s.fly(...)`.
- **Never ask the learner questions inside the lesson**; questions only in `practice`.
- `checks.known` must use an external source's worked example. Fix the model if a check fails — never weaken a check.
- No `Math.random`, `Date`, timers, `async`, DOM, HTML/CSS. Positions are world units (x 0–1600, y 0–770), regions or
  relative placements.
- Lesson text in the user's language (`meta.lang`); API names stay English.
- Do not ask the user clarifying questions unless the topic is genuinely ambiguous; choose a good worked example yourself.

# Appendix A — Guide


You write **one file, `lesson.js`**. The engine (a framework) turns it into an interactive, offline learning lab.
The exact API is in `engine-api.d.ts`. A complete small lesson is in `example-lesson.js`. Use only what the API declares.

## 1. How your file runs

```js
export default defineLesson({ meta, glossary, inputs, model, checks, scene, script, practice })
```

| Part | Runs | You write |
|---|---|---|
| `model(inputs, t)` | at load and whenever the learner changes inputs | the concept's computation, pure. Build numbers with `t` (`t.input`, `t.mul`, `t.add`, `t.fn`, `t.dot`, `t.event`). |
| `checks` | at build time (+40 random inputs) | `known`: ≥ 1 case from an external source with expected values; `invariants`: rules that always hold |
| `scene(stage, data, inputs)` | once per build | the starting objects; return handles for `script` |
| `script(lesson, refs, data, inputs)` | once per build, **synchronously** | chapters → steps → micro steps: narration + verbs |

Each verb inside a step is appended to that step's timeline **in call order**. Use `s.together(() => {...})` for simultaneous
actions. The engine handles Next / Back / speed / detail level / scrubbing / tinkering automatically.

**Never hard-code a number that comes from the model.** Use `{{valId}}` in text and pass `Val`s to verbs. When the learner
changes an input, the whole lesson is recomputed and everything stays consistent.

Forbidden: `Math.random`, `Date`, timers, `async/await`, `fetch`, `import`, DOM access, HTML/CSS.
The build rejects them with a message telling you what to use instead.

## 2. Teaching rules (non-negotiable)

1. **What and why before how.** First chapters: what is this, why does it exist, what problem does it solve.
2. **Zero knowledge.** Every term the learner might not know is in `glossary` and introduced with `[[termId]]` before the
   process uses it. Every formula symbol has a glossary entry. Plain words, short sentences.
3. **One new idea per stop.** If a sentence introduces two ideas, split it into two steps.
4. **Formulas twice:** symbols (`s.formula.show(tex)`) **and** words (`words:`). Write `\cdot` between factors.
5. **Show where every number comes from:** `s.fly(source, s.formula.slot(id))` or `s.fly(val, targetObject)`.
6. **Never ask the learner questions in the lesson** ("Tahminin nedir?" is forbidden). The lesson never waits for input.
   Tinkering is optional (inputs drawer, draggable plot points). Questions belong only in `practice`.
7. **Teach the pattern.** Chapter titles are the pipeline of the process (they form the roadmap strip). End with a short
   chapter that names the pattern in one sentence (e.g. "multiply → sum → squash").
8. **Mark what must be memorised** (`glossary.memorize: true` or `lesson.memorize({...})`).
9. **Language:** all learner text in `meta.lang`. Keep established technical terms as the field uses them.
   For suffixes write `[[term|shown text]]`, e.g. `[[cell|hücreden]]`.

Recommended arc (adapt to the topic): **Question → What → Why → Parts → Process (one chapter per stage) → Result → Pattern**,
plus `practice`.

## 3. Stops and detail levels

```js
lesson.chapter('hidden', 'Gizli katman', s => {              // chapter = level 1, always a stop
  s.say('Her gizli nöron girdilerini tartıp toplar, sonra sıkıştırır.')      // overview narration
  s.step('h1', { title: 'İlk nöron', level: 2 }, s => {
    s.say('İlk nöronun [[wsum]] değeri {{z1}}.')                             // normal narration
    s.step('h1-x1', { level: 3 }, s => {
      s.say('[[input]] {{x1}}, [[weight]] {{w11}} ile çarpılır: {{p11}}.')   // micro narration
      s.fly(net.nodeValue('x1'), s.formula.slot('x1'))
    })
  })
})
```

- Every chapter and step is a stop. The learner navigates with three rows of ‹ › buttons: **Chapter** (level 1),
  **Step** (level ≤ 2) and **Micro** (every stop). A coarse jump plays the whole unit quickly and shows the narration of
  that unit's chapter/step, so write level-1/2 narration as a summary of everything inside.
- **Every chapter and step needs its own `s.say(...)`, written for its level.** A parent's text summarises its children.
- **Put a step's own actions before its child steps.** Actions after a child belong to the previous stop (build warns).

## 4. Objects, verbs, effects, selection

**Read `motion-grammar.md` first.** Prefer verbs that transform (`to`, `moveTo`, `along`, `setValue`, `fly`, `split`,
`recolor`, camera) over verbs that only fade (`show/hide/dim`).

- **Objects persist.** Never re-create something that exists — move it, change it, tag it, dim it.
- Verbs: `show hide dim undim highlight unhighlight pulse recolor remove moveTo along scaleTo setValue setText tag untag split clone`.
- Continuous effects stay on until turned off: `glow() jitter('low'|'mid'|'high') breathe() flow()`, off with `glow(false)` …
- `split()` returns `[a, b]`; `a` is the original; tags, colour and effects are inherited; `dir: 'free'` packs a colony.
- Focus = **dim the rest + highlight the subject**: `net.nodes().except('h1').dim(); net.node('h1').highlight()`.
- Selection: `stage.select('cell')` (your kind), `'.cancer'` (tag), `'#h1'` (id), then `.except() .tagged() .where()
  .generation() .first() .sample()`; verbs on a selection apply to all, `{ stagger: 'fast' }` spreads them.
- Built-in part kinds are prefixed (`table-cell`, `net-node`, `seq-message` …); give your own shapes a `kind`.
- Custom shapes: `stage.shape('<ellipse rx="50" ry="30"/><circle class="nucleus" r="12"/>', { kind: 'cell', role: 'cell', size: 70 })`,
  then `obj.part('nucleus')`.
- Colours: never write colours. `role` = a glossary key with `concept: true` (concept = colour everywhere: the same
  colour for a concept in the scene, in labels and in formula slots). Also `neutral accent danger success warn`.

## 5. Placement and layout

- World coordinates: `{ x, y }` with x 0–1600 (left → right) and y 0–770 (top → bottom). Use them freely for your own
  drawings (see `example-lesson.js`). Regions and relative placements are conveniences.

- Regions (world 1600 × 770): `main` (all), `center`, `left`, `right`, `top`, `bottom`, `inset` (top-right corner).
  `{ region: 'main', u: 0.3, v: 0.5 }` with u, v in 0..1. Components (table, plot, net, graph, sequence …) **fill their
  region** — give two components two different regions.
- Relative: `{ near: obj, side: 'right', gap: 'md' }`, `{ between: [a, b] }`, `{ inside: container }`.
- Plot coordinates: `plot.point({ x, y })` or `{ plot, x, y }`.
- Keep ≤ ~5 labelled things in view at once. Use `dim`, `hide` and the camera to declutter.
- The formula bar lives below the stage; one formula at a time.

## 5b. Component notes

**neuralNet** lays out columns of neurons (left → right) inside its region. Parts: `node(id)` (circle, kind `net-node`),
`nodeValue(id)` (the number inside), `edge(a, b)`, `weight(a, b)` (chip on the edge, hidden unless `weights: 'always'`),
`bias(id)` (small badge at the neuron's lower right). Default ids: `x1 x2 …`, `h1 h2 …` (one hidden layer) or
`h1_1 h1_2 … h2_1 …` (several), `y1 …`. Two common bias conventions:
- *b per neuron* (z = Σ w·x + b): keep `bias: true` (default) and give `values.biases`.
- *bias input x0 = −1 with weight θ0* (z = θ0·(−1) + Σ θ·x): set `bias: false`, add `x0` as the first input
  (`ids: [['x0','x1','x2'], …]`, `values.inputs.x0 = -1`) so its weights appear on edges like the others.
Large nets: prefer `weights: 'on-focus'` and show only the weights of the neuron you are explaining.

**plot** maps domain coordinates into its region; `curve(f)` draws in when created inside a step; `point(..., { draggable:
{ inputX: 'x' } })` lets the learner drag and the whole lesson recomputes with the new input.

**sequence** stacks messages top-down in call order; **stateMachine** switches to a vertical layout when labels need room.

## 6. Camera

The camera changes the view, never the objects: `stage.camera.focus(obj | selection)`, `.frame('left' | selection)`,
`.follow(obj)` (until step end), `.reset()`, `.magnify(obj)` (picture-in-picture). Use it for close-ups (one neuron, one
cell), then `reset()`. Labels grow only a little when zoomed (`damped`); `minZoom` shows details only when zoomed in.

## 7. Correctness

- `checks.known`: values from a real external source (cite it). Not "2+2=4"-style self-checks only.
- `checks.invariants`: properties of the concept (probabilities sum to 1, sequence numbers increase, result within bounds…).
- The build runs both on defaults, 40 random inputs and the practice inputs, and fails on any violation.

# Appendix B — Motion grammar


A lab that only fades things in and out is a slide show. The learner must **watch the idea happen**. The engine already
makes every verb move well (pop-in with overshoot, lines that draw themselves, numbers that count, values that fly on an
arc and land with a bounce, cascades, colour tweens). Your job is the **choreography**: what transforms into what, in
which order.

## The seven rules

1. **One orchestrated moment per stop.** Each stop has one main movement (the thing the narration is about). Everything
   else supports it and starts slightly before or after it.
2. **Transform, don't replace.** The same quantity is the same object for the whole lesson. Move it, grow it
   (`obj.to({ height })`), recolour it, split it, merge it, count it (`setValue`). Never hide one thing and show another
   in its place.
3. **Every number comes from somewhere.** Source swells → the value flies (`s.fly`) → lands in the formula or the target
   → the result is born there (`formula.fill`, `value.setValue`) → it settles. No number appears out of nowhere.
4. **Build the scene as you speak.** An object is born on the beat its name is said. Do not create everything visible in
   `scene()`: create it hidden and `show()` it in the step that introduces it.
5. **No cuts.** If you need a second picture, move the first one aside (`moveTo`, `scaleTo`) or use the camera
   (`stage.camera.focus(...)` for a close-up, `camera.reset()` to come back). Never swap whole scenes with hide/show.
6. **Rhythm:** anticipation (0.2–0.3 s) → main action (0.6–1.2 s) → settle and result (0.3–0.5 s) → breath. The engine
   overlaps consecutive actions slightly; use `s.together` only for things that truly happen at once, and
   `{ stagger }` on selections for cascades.
7. **The result after its cause.** Wrap the result in narration with `‹…›`: it appears when the stop's animation has
   finished, so the text never announces what the learner has not seen yet.

## Verbs that make motion (prefer these)

| Want | Write |
|---|---|
| something is born | `obj.show()` (pops in; lines/arrows/curves draw themselves) |
| a quantity grows/shrinks | `bar.to({ y: -h, height: h })`, `circle.to({ r })`, `obj.scaleTo(k)` |
| a shape changes form | `path.to({ d: newD })` (same command structure morphs) |
| a number changes | `chip.setValue(val)` (counts) |
| a value goes somewhere | `s.fly(source, s.formula.slot('x'))`, `s.fly(val, targetChip)` |
| an object travels | `obj.moveTo({ x, y })`, `obj.along(curve)`, `obj.along(t => ({ x, y }), { plot })` |
| a group appears | `sel.show({ stagger: 'fast' })` (cascade) |
| one becomes two / many | `obj.split()`, `sel.split({ dir: 'free' })` |
| category / state change | `obj.recolor(role)` (colour tween), `obj.tag('x')` |
| look closer | `stage.camera.focus(obj)` … `stage.camera.reset()` |
| something is active | `edge.flow()`, `obj.glow()` (turn off afterwards) |
| attention | `obj.pulse()`, `highlight()` — supporting only, never the main action |

`dim()` / `highlight()` / `hide()` are supporting moves. **A stop made only of them is a slide** (QA warns).

## Anti-patterns (QA or review will flag them)

- a stop where things only fade in/out; three or more unrelated movements at the same time
- text on top of text; a result shown before the movement that produces it
- a value that pops up without a source; an object "teleporting" (hide here, show there)
- empty boxes or placeholders left on screen; everything visible from the first stop

## Visual design is yours

Components (`neuralNet`, `plot`, `table`, `graph`, …) are **starting points**, not the only way. If the topic needs a
different picture (hexagonal cells, a water tank, a pipeline of machines, a pizza cut in slices), draw it with
`stage.shape(svg, { kind })` at world coordinates `{ x, y }` (x 0–1600, y 0–770) and animate it with the verbs above.
Encode meaning visually (size ∝ value, thickness ∝ weight, colour = concept). Keep at most ~5 labelled things in view.

# Appendix C — Example lesson (complete, builds and passes QA)

```js
// Example lesson: the arithmetic mean, taught by TRANSFORMING things (not by fading slides).
// Copy its structure and its motion habits, not its topic:
//  - objects are born when they are named (pop in), lines draw themselves, numbers count,
//  - values fly from where they live into the formula, results are born from the formula,
//  - the key idea is shown as a transformation (bars level out to the mean), the camera zooms for a detail.
const BASE = 610, X0 = 360, GAP = 200, PX = 40 // world units: baseline y, first bar x, bar spacing, px per hour
const barX = i => X0 + i * GAP

export default defineLesson({
  meta: { title: 'Ortalama: hepsi eşit paylaşsaydı', lang: 'tr', goal: 'Bir sayı listesinin aritmetik ortalamasını hesaplamak ve ne anlama geldiğini görmek.' },

  glossary: {
    value: { term: 'değer', short: 'Listedeki tek bir sayı (burada bir günde çalışılan saat).', concept: true },
    sum: { term: 'toplam', short: 'Bütün değerlerin art arda eklenmesiyle çıkan sayı.', symbol: '\\Sigma', concept: true },
    count: { term: 'adet', short: 'Listede kaç değer olduğu.', symbol: 'n' },
    mean: { term: 'ortalama', short: 'Toplamın adede bölümü: herkes eşit paylaşsaydı her birine düşecek miktar.', symbol: '\\bar{x}', concept: true, memorize: true },
  },

  inputs: {
    d1: { default: 4, min: 0, max: 10, step: 1, term: 'value' },
    d2: { default: 7, min: 0, max: 10, step: 1, term: 'value' },
    d3: { default: 3, min: 0, max: 10, step: 1, term: 'value' },
    d4: { default: 8, min: 0, max: 10, step: 1, term: 'value' },
    d5: { default: 8, min: 0, max: 10, step: 1, term: 'value' },
  },

  model(inp, t) {
    const vals = ['d1', 'd2', 'd3', 'd4', 'd5'].map(k => t.input(k, inp[k]))
    const sum = t.add('sum', ...vals)
    const n = t.const('n', vals.length)
    const mean = t.div('mean', sum, n)
    return { vals, sum, n, mean }
  },

  checks: {
    known: [{ source: 'Ders kitabı örneği: 4, 7, 3, 8, 8 → toplam 30, ortalama 6', inputs: { d1: 4, d2: 7, d3: 3, d4: 8, d5: 8 }, expect: { sum: 30, mean: 6 } }],
    invariants(d, inp, fail) {
      const xs = d.vals.map(v => v.value)
      if (d.mean.value < Math.min(...xs) - 1e-9 || d.mean.value > Math.max(...xs) + 1e-9) fail('ortalama en küçük ile en büyük değer arasında olmalı')
      if (Math.abs(xs.reduce((s, x) => s + (x - d.mean.value), 0)) > 1e-9) fail('sapmaların toplamı 0 olmalı')
    },
  },

  scene(stage, d) {
    // free visuals: plain shapes at world coordinates (no component needed)
    const axis = stage.shape(`<line x1="0" y1="0" x2="${GAP * 5}" y2="0" stroke="var(--ink-3)" stroke-width="3"/>`, { at: { x: X0 - GAP / 2 + (GAP * 5) / 2, y: BASE }, hidden: true })
    const bars = d.vals.map((v, i) => stage.shape('<rect x="-48" y="-1" width="96" height="1" rx="10"/>', { id: `bar${i + 1}`, kind: 'bar', role: 'value', at: { x: barX(i), y: BASE - 0.5 }, hidden: true }))
    const tags = d.vals.map((v, i) => stage.value(0, { id: `tag${i + 1}`, role: 'value', at: { x: barX(i), y: BASE - 34 }, hidden: true }))
    const days = ['Pzt', 'Sal', 'Çar', 'Per', 'Cum'].map((s, i) => stage.label(s, { at: { x: barX(i), y: BASE + 36 }, size: 'sm', hidden: true }))
    const meanLine = stage.shape(`<line x1="0" y1="0" x2="${GAP * 5}" y2="0" stroke-width="4" stroke-dasharray="14 10"/>`, { role: 'mean', at: { x: X0 - GAP / 2 + (GAP * 5) / 2, y: BASE - d.mean.value * PX }, hidden: true })
    const meanTag = stage.value(d.mean, { role: 'mean', size: 'lg', at: { x: X0 + GAP * 5 - 20, y: BASE - d.mean.value * PX - 40 }, hidden: true })
    const sumChip = stage.value(d.sum, { role: 'sum', size: 'lg', at: { region: 'top', u: 0.82, v: 0.45 }, hidden: true })
    return { axis, bars, tags, days, meanLine, meanTag, sumChip }
  },

  script(lesson, { axis, bars, tags, days, meanLine, meanTag, sumChip }, d) {
    const stage = lesson.stage
    const H = v => v * PX

    lesson.chapter('question', 'Soru', s => {
      s.say('Beş gün boyunca her gün kaç saat çalıştığını yazdık. Peki "genelde günde kaç saat çalışıyorum" sorusunun tek bir cevabı olabilir mi?')
      axis.show()
      stage.select('label').show({ stagger: 'fast' })
      // bars grow from the baseline one after another; their numbers count up while they grow
      bars.forEach((b, i) => s.together(() => {
        b.show({ speed: 'fast' })
        b.to({ y: -H(d.vals[i].value), height: H(d.vals[i].value) }, { ease: 'back.out(1.4)' })
        tags[i].show({ speed: 'fast' }).moveTo({ x: barX(i), y: BASE - H(d.vals[i].value) - 34 })
        tags[i].setValue(d.vals[i])
      }))
    })

    lesson.chapter('sum', 'Topla', s => {
      s.say('Önce bütün [[value]] sayılarını bir araya topluyoruz: bu sayıya [[sum]] denir. ‹Toplam {{sum}} saat.›')
      s.formula.show('\\slot{sum}{\\Sigma} = \\slot{d1}{x_1} + \\slot{d2}{x_2} + \\slot{d3}{x_3} + \\slot{d4}{x_4} + \\slot{d5}{x_5}', { words: 'toplam = bütün değerlerin art arda eklenmesi' })
      s.step('sum-fly', { title: 'Sayılar formüle', level: 3 }, s => {
        s.say('Her çubuğun sayısı formüldeki yerine uçuyor.')
        tags.forEach((tg, i) => s.fly(tg, s.formula.slot(`d${i + 1}`)))
      })
      s.step('sum-born', { title: 'Toplam doğar', level: 3 }, s => {
        s.say('Beş sayı birleşince [[sum]] ortaya çıkar: ‹{{sum}}›.')
        s.formula.fill('sum', d.sum)
        s.fly(d.sum, sumChip)
        sumChip.show().pulse()
      })
    })

    lesson.chapter('divide', 'Böl', s => {
      s.say('[[sum]] değerini [[count]] sayısına, yani 5 güne bölüyoruz. Çıkan sayı [[mean]]: ‹günde {{mean}} saat›.')
      s.formula.show('\\slot{mean}{\\bar{x}} = \\frac{\\slot{sum}{\\Sigma}}{\\slot{n}{n}}', { words: 'ortalama = toplam ÷ adet' })
      s.fly(sumChip, s.formula.slot('sum'))
      s.formula.fill('n', d.n)
      s.formula.fill('mean', d.mean)
      s.together(() => { meanLine.show(); meanTag.show() })
    })

    lesson.chapter('level', 'Eşitle', s => {
      s.say('Ortalama ne demek? Çok çalışılan günler fazlalarını az çalışılan günlere verseydi, bütün çubuklar ‹tam {{mean}} saat› yüksekliğinde eşitlenirdi.')
      // the key idea as a transformation: every bar levels out to the mean, its number counts to the mean
      bars.forEach((b, i) => s.together(() => {
        b.to({ y: -H(d.mean.value), height: H(d.mean.value) }, { ease: 'power3.inOut' })
        tags[i].moveTo({ x: barX(i), y: BASE - H(d.mean.value) - 34 })
        tags[i].setValue(d.mean)
      }))
      bars.forEach(b => b.recolor('mean'))
    })
```

# Appendix D — API (engine-api.d.ts, exact)

```ts
/**
 * Visual Agent Teacher (VAT) — lesson API v0.1.
 *
 * You write ONE file, `lesson.js`: `export default defineLesson({ ... })`. VAT is a framework: the engine calls
 * your functions (at load, again when the learner changes inputs). You never write HTML, CSS, DOM code or timers.
 *
 * EXECUTION RULES
 *  - `model` is pure and deterministic. Every number shown on screen comes from it (or from inputs).
 *  - `scene` runs once and creates the starting objects. Objects persist for the whole lesson.
 *  - `script` runs SYNCHRONOUSLY. Each verb called inside a chapter/step build function is appended to that step's
 *    timeline in call order (one after another). Use s.together(() => { ... }) for simultaneous actions.
 *    No async/await, no timers, no Math.random/Date.
 *  - Positions are world units ({ x, y }: x 0–1600, y 0–770), regions, { region, u, v }, { near, side }, { between },
 *    { inside } or plot coordinates { plot, x, y }. Never screen pixels.
 *  - Unknown members throw a clear error ("Obj has no member 'bol'. Did you mean 'split'?").
 *
 * MOTION (see motion-grammar.md): show() pops in / draws lines, setValue() counts, fly() arcs and lands, moveTo/along
 *  travel, to() tweens any attribute (sizes, paths, colours), recolor() fades colours, selections cascade. Consecutive
 *  actions overlap slightly. A stop that only fades things in/out plays like a slide: QA warns.
 *
 * STOPS AND DETAIL LEVELS
 *  - Every chapter and step is a stop. The learner navigates with three rows: Chapter (level 1), Step (level ≤ 2) and
 *    Micro (every stop). A coarse jump plays the whole unit quickly and shows the narration of that unit's node.
 *  - Every chapter/step MUST have its own s.say(...) written for its level (a parent's text is a summary of its
 *    children, not a copy). Build fails otherwise.
 *  - Put a step's own actions BEFORE its child steps. Actions written after a child step belong to the previous stop.
 *  - s.summary(() => {...}): what a parent shows when ALL its children are folded; the children's effects are then
 *    applied instantly after it, so the end state is always the same at every detail level.
 */
export {};

declare global {
  function defineLesson<I extends Record<string, number>, T, R>(def: VAT.LessonDef<I, T, R>): VAT.LessonDef<I, T, R>;
  const vat: VAT.Toolkit;

  namespace VAT {
    // ─────────────────────────────── Lesson definition ───────────────────────────────

    interface LessonDef<I extends Record<string, number>, T, R> {
      meta: Meta;
      /** Every term a zero-knowledge learner may not know. Keys are term ids: used in [[id]] and as `role`. */
      glossary: Record<string, GlossaryEntry>;
      /** Tweakable inputs (example values + allowed range). The learner can change them (Tinker drawer, draggable points). */
      inputs?: { [K in keyof I]: InputSpec };
      /** Pure computation of the concept. Build numbers with `t` so each value knows its sources. Return what scene/script need
       *  (Vals, events, plain data, and pure helper functions such as curves are all fine). */
      model(inputs: I, t: TraceBuilder): T;
      /** Independent verification. Build fails when a check fails. */
      checks: Checks<I>;
      /** Create the starting objects once; return handles for `script`. */
      scene(stage: Stage, data: T, inputs: I): R;
      /** The lesson: chapters → steps → micro steps, with narration and choreography. */
      script(lesson: LessonBuilder, refs: R, data: T, inputs: I): void;
      /** Optional exercise: the same problem with new values; the learner types answers. */
      practice?: Practice<I>;
    }

    interface Meta {
      title: string;
      /** Language of every learner-facing string, e.g. 'tr' or 'en'. Numbers use its decimal separator. */
      lang: string;
      /** One sentence: what the learner can do after the lesson. */
      goal: string;
    }

    interface GlossaryEntry {
      /** Display form in the lesson language, e.g. 'ağırlık'. */
      term: string;
      /** Plain definition for a zero-knowledge learner (1–2 sentences). Shown on hover. */
      short: string;
      long?: string;
      /** Symbol in TeX, e.g. 'w_{ij}'. */
      symbol?: string;
      /** true → gets its own concept colour (max ~6). Objects/slots with role = this key use it. */
      concept?: boolean;
      /** true → listed on the "Memorise" card. */
      memorize?: boolean;
    }

    interface InputSpec {
      default: number;
      min: number;
      max: number;
      step: number;
      /** Glossary key naming this input in the UI. */
      term?: string;
    }

    // ─────────────────────────────── Model & trace ───────────────────────────────

    /** A number that remembers where it came from. Display with {{id}} in text or pass the Val to verbs. */
    interface Val {
      readonly id: string;
      /** Exact value (use for computation). */
      readonly value: number;
      readonly sources: readonly string[];
      /** Display string (lesson-language rounding). Display only — never feed back into math. */
      fmt(dp?: number): string;
    }

    interface TraceEvent {
      readonly id: string;
      readonly index: number;
      readonly payload: Record<string, unknown>;
    }

    /** All ids must be unique ('phase1', 'phase2' …, or 'z' + i in loops). */
    interface TraceBuilder {

      const(id: string, value: number): Val;
      add(id: string, ...xs: Val[]): Val;
      sub(id: string, a: Val, b: Val): Val;
      mul(id: string, ...xs: Val[]): Val;
      /** Throws on division by zero: handle that case explicitly. */
      div(id: string, a: Val, b: Val): Val;
      pow(id: string, base: Val, exponent: Val | number): Val;

      dot(id: string, xs: Val[], ws: Val[]): Val;
      /** Any other function: t.fn('a1', 'sigmoid', z => 1 / (1 + Math.exp(-z)), z1) */
      fn(id: string, name: string, f: (...xs: number[]) => number, ...args: Val[]): Val;
      /** Non-numeric event, in order (protocol message, cell phase, state change). Payload values may be numbers/strings. */
      event(id: string, payload?: Record<string, unknown>): TraceEvent;
    }

    interface Checks<I> {

      tasks: Array<{ id: string; prompt: string | ((inputs: I) => string); answer: string; tolerance?: number }>;
    }

    interface Rand {
      float(min: number, max: number, step?: number): number;
      int(min: number, max: number): number;

    // ─────────────────────────────── Placement & options ───────────────────────────────

      /** Everything called inside starts at the same time. */
      together(build: () => void): void;
      /** A short beat (≈0.45 s per beat). */
      pause(beats?: number): void;
      /** Animation for this step when all its children are folded (coarser detail). */
      summary(build: () => void): void;
      readonly formula: FormulaBar;
      /** Number journey: a chip flies from an object (or the object showing a Val) to a formula slot (fills it) or to a
       *  value-like object (replaces its number: value chip, table/grid cell, net value/weight/bias). Onto other objects it
       *  just lands with a pulse. */
      fly(from: Obj | Val, to: Slot | Obj, o?: VerbOpts): void;
      /** Escape hatch: append a GSAP animation (vat.gsap.to(...)) to this step; speed/Back/skip still work. */
      add(anim: unknown): void;
    }

    interface FormulaBar {
      /** TeX subset with slots \slot{id}{tex}: ^{} _{} \frac{}{} \sqrt{} \text{} \cdot \times greek letters \sum …
       *  Write \cdot between factors. A slot whose id is a trace id reserves room for that value.
       *  words: the same formula in plain words (markup allowed). */
      show(tex: string, o?: { words?: string }): void;
      slot(id: string): Slot;
      fill(slotId: string, v: Val | number | string): void;
      highlight(...slotIds: string[]): void;
      clear(): void;
    }

    interface Slot {
      readonly slotId: string;
    }

    // ─────────────────────────────── Toolkit & extension ───────────────────────────────

    interface PanelAdapter {
      mount(el: HTMLElement): void;
      render(stepId: string, data: unknown): void;
      destroy?(): void;
    }

    interface Toolkit {
      /** GSAP, for raw animations added with s.add(). Browser only. */
      readonly gsap: any;
      readonly version: string;
      /** Format a number in the lesson language. */
      fmt(n: number, dp?: number): string;
      defineVerb(name: string, impl: (target: Obj, opts: Record<string, unknown>) => void): void;
      defineComponent(name: string, build: (stage: Stage, spec: Record<string, unknown>) => Obj): void;
      extendComponent(base: string, name: string, extend: (instance: any, spec: Record<string, unknown>) => any): void;
    }
  }
}
```
